# Go 代码编写规范

先阅读目标代码、调用方、项目 AGENTS.md 和相邻实现；保留已有业务行为及用户未提交的修改。代码涉及模型或分层接口时，同时遵循项目 Go 模型分层技能。

## 组织与可读性

- 使用 `gofmt`，遵循标准 Go 命名和现有包的命名风格。导入按标准库、第三方、项目包分组。
- 函数围绕清晰职责组织；当配置解析、输入校验、业务处理、资源生命周期或并发控制混在一起时，按实际职责提取私有函数。避免为单行表达式增加无意义的抽象。
- 使用提前返回减少嵌套；拆分复杂条件并采用明确的变量名。对有业务含义的重复数值使用具名常量，避免为每个字面量创建常量。
- 每个函数和方法都编写中文函数注释，说明用途及必要的行为约束；以函数名开头，符合 Go 注释约定。注释保持准确简洁，不逐句复述实现。
- 函数内部按逻辑动作分段：完成一个独立动作后，用空行与下一个动作分隔；紧密相关的赋值、调用和错误检查保持在同一段，避免每行之间都插入空行。
- 避免无关格式调整及大范围重命名。

## 正确性与验证

- 显式处理错误和资源关闭；保留错误语义、上下文取消、超时、并发同步和调用顺序。不要为了简化结构改变外部协议或接口。
- 日志提供有用上下文，但不输出凭据、密钥或敏感载荷。按项目 Controller、Service、DAO 分层放置逻辑，DAO 显式指定表名。
- 对受影响的行为运行有针对性的测试及适用 build tag 的构建；当重构涉及并发、认证或协议时，优先验证这些边界。无法验证时说明原因。
